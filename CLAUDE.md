# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Python 3.12 + `uv`. CLI `monitorul-ii` with five subcommands: `fetch` (scrape PDFs by date), `convert` (PDF → markdown with extraction-friendly YAML frontmatter), `classify` (type-detect MDs into the v1.13.0 extraction-schema buckets), `extract` (MD → strict-validated JSON sidecar; identity producer mints stable per-record `id` / `content_fingerprint` / `slug` for downstream Elasticsearch indexing), and `link` (linker — three passes: report→session back-links + vote-pair deferral chains + art-N intra-doc cross-reference resolution; linker v0.2.0 / xref_linker v0.1.0). Hatchling-backed package at `src/monitorul_ii/`. All 6 document types ship per-type extractors at v0.1+.

## Layout

- `src/monitorul_ii/scraper.py` — pure functions: `fetch_index`, `parse_issues`, `download_pdf`, `scrape_day`, plus `_with_retry`. Sha256 + size are computed in the streaming download. No CLI concerns.
- `src/monitorul_ii/converter.py` — pure functions: `parse_filename`, `enrich_meta`, `clean_markdown`, `convert_pdf`, `convert_all`, `collect_pdfs`. Wraps `pymupdf4llm.to_markdown` and applies an MO-specific cleanup pass + YAML frontmatter prepend. No CLI concerns.
- `src/monitorul_ii/classifier.py` — pure functions: `parse_issue_suffix`, `classify`, `classify_file`, `collect_mds`, plus `ClassifyResult` (with `is_ambiguous(threshold)`). Detection rules from `docs/extraction-schema.md` build-order step 1: filename suffix (`c`/`R`) + body markers (`(STENOGRAMA)`, `DEZBATERI PARLAMENTARE`, `ȘEDINȚE COMUNE …`, `(RAPOARTE DE ACTIVITATE)`, `LISTA ÎNTREBĂRILOR ADRESATE`, `SINTEZA LUCRĂRILOR COMISIILOR`). Reads only the first `HEADER_WINDOW_BYTES=10_000` of each MD. `_COMPATIBLE_RUNNERS_UP` suppresses "ambiguous" flagging when the runner-up is structurally implied by the winner (joint_session ⊃ stenogram; report_facsimile is received in joint/single sessions). No CLI concerns.
- `src/monitorul_ii/extraction/` — subpackage. `pipeline.py`: dispatcher (`extract(md_path, *, force, override_type, write, identity_only)` → `ExtractResult`); orchestrates classify → per-type extractor → shared boilerplate merge → coverage compute → identity stamp (`assign_identity` mints per-record `id` / `content_fingerprint` / `slug`, reads any prior sidecar to enforce slug-once) → envelope build → JSON Schema validate → atomic sidecar write. `identity_only=True` is the schema-1.13.0 backfill fast path: skips classify + per-type extractor and re-runs only `assign_identity` against an existing sidecar's body, bumping `extractor_versions.identity` and `schema_version` to 1.13.0. `identity.py` (v0.1.0): `IDENTITY_VERSION` constant; `mint_record_id(doc_id, grain, *, ordinal, seq, natural_key)` for the canonical `mo://YYYY/PART/ISSUE#<suffix>` patterns from Q2 of `docs/elasticsearch-indexing.md` (document / report / agenda_item / activity / vote / interpellation[/_seq] / question[/_seq] / committee_meeting / committee_agenda_item); `compute_content_fingerprint(text)` = sha256-hex-12 of NFC-normalized + whitespace-collapsed text (forensic — survives whitespace tweaks, changes when content changes); `compute_short_id(year, issue, ordinal, seq)` = base32-lowercase-stripped 10-char tag for URL tails; `mint_slug(title, short_id, max_keyword_chars=60)` = ASCII-fold + 8-token cap + `-<short_id>` suffix (empty/punct titles fall back to short_id alone); `assign_identity(body, doc_type, doc_id, year, issue, *, prior_sidecar)` walks the body, mutates each grain in place with `id` / `content_fingerprint` / `slug`, returns the envelope identity dict `{record_id: doc_id}` for the caller to drop into `extraction.identity`. **Slug-once contract**: when `prior_sidecar` is present, slugs whose `id` matches a prior record's `id` are preserved verbatim — extractor regex tweaks that change titles never produce slug churn (locks published URLs across iteration). ## How the scraper talks to the site

There is no documented API. Reverse-engineered from the e-monitor page:

- **Index endpoint**: `POST https://monitoruloficial.ro/ramo_customs/emonitor/get_mo.php` with form body `today=YYYY-MM-DD` and a `Referer: https://monitoruloficial.ro/e-monitor/` header. Returns an HTML fragment — one `<div class="card-body">` per Partea, with `<a href="/Monitorul-Oficial--P<part>--<num>--<year>.html">` links.
- **PDF**: GET that `.html` URL — the response body **is** the PDF (`Content-Type: application/pdf`). The `.html` extension is misleading.
- Issue numbers can carry suffixes (`358Bis`, `12c`) — the parser regex accepts `[0-9A-Za-z]+`.
- Empty days (weekends, no Partea II that day) return zero issues; not an error.

## Commands

- Install / sync deps: `uv sync`
- Fetch PDFs: `uv run monitorul-ii fetch <YYYY-MM-DD> [--until YYYY-MM-DD] [--out DIR] [--part II] [--delay 0.5] [--proxy URL | --no-proxy] [--bucket NAME | --no-upload] [--db PATH | --no-db] [--reverse] [--force] [--rescrape-recent N] [--retry-gone]`
- Convert PDFs to markdown: `uv run monitorul-ii convert <path> [<path> ...] [--force] [-j N | --workers N] [--reverse] [--bucket NAME | --no-upload]` — paths are files or directories; directories are globbed `*.pdf` (non-recursive). Default `-j` is `os.cpu_count()`; conversions run in a `ThreadPoolExecutor`. `--reverse` flips the final PDF list (newest→oldest given the date-prefixed filenames) — same semantics as `fetch --reverse`.
- Classify converted MDs: `uv run monitorul-ii classify <path> [<path> ...] [--outliers] [--ambiguity-threshold MARGIN] [--reverse]` — sweep MDs and emit one JSONL row per file to stdout (`top_type`, `top_score`, `second_type`, `second_score`, `ambiguous`, `all_scores`, `matched_signals`). `--outliers` filters to docs that classified as `other` or are ambiguous (top-vs-second margin below `--ambiguity-threshold`, default 0.2) — those are the unknown unknowns the schema-discovery loop wants to inspect. `--reverse` walks newest→oldest like the other subcommands.
- Extract structured JSON sidecars: `uv run monitorul-ii extract <path> [<path> ...] [--force] [--type TYPE] [--coverage-below MARGIN] [--reverse] [--identity-only] [--bucket NAME | --no-upload]` — dispatch each MD to its per-type extractor and write `<basename>.extraction.json` next to it. `--force` overrides the version-aware idempotency gate; `--type` overrides the classifier on a per-run basis (sparingly); `--coverage-below MARGIN` adds a JSONL outlier line to stdout for each doc whose `claimed_pct < MARGIN`; `--reverse` walks newest→oldest; `--identity-only` is the schema-1.13.0 backfill fast path — skips the per-type extractor and re-runs only `assign_identity` against the existing sidecar's body, bumping `extractor_versions.identity` and `schema_version` to 1.13.0. v0.1 ships extractors for all six document types — `question_register`, `plenary_stenogram`, `plenary_joint_session`, `committee_synthesis`, and `report_facsimile` (100% coverage of the typed corpus). The skip-with-reason path remains in place for any future type that ships a classifier rule before its extractor lands.
- Linker: `uv run monitorul-ii link <path> [<path> ...] [--force] [--dry-run] [--report-only | --vote-only | --xref-only] [--bucket NAME | --no-upload]` — walk `*.extraction.json` sidecars and run **three passes** by default. Pass 1 (report→session, cross-doc) builds an index of `plenary_joint_session` + `plenary_stenogram` sidecars by `metadata.session_date` and fills each `report_facsimile` sidecar's `received_at.received_in_document` with the matching `document_id`. Pass 2 (vote-pair, cross-doc, linker v0.2.0+) builds a vote index keyed by **bill cite only** (`f"bill:{number}/{year}"`, with `motion:{kind}:{title-hash}` for motion-class votes carrying a quoted title ≥12 chars; other ref types and agenda-title hashes intentionally excluded — see linker.py module docstring for the false-positive analysis), pairs deferred votes (`outcome=deferred`) with their resolvers in subsequent stenograms within the 60-day window (`DEFERRAL_WINDOW_DAYS=60`), and writes `defers_to` (forward link) on the deferring vote + `resolves[]` (back-link, list of origin document_ids) on the resolver. Multi-deferral chains: A→B→C produces `A.defers_to=B`, `B.defers_to=C`, `C.resolves=[A, B]` (chain reversal). Pass 3 (cross-reference, intra-doc, xref_linker v0.1.0+) walks each plenary sidecar's reference lists and resolves bare `art. N` unknowns to the nearest preceding non-unknown reference IN THE SAME LIST (`primary_references[]` / `references_mentioned[]`); writes `unknown.resolved_to.char_offsets` (a pointer at the anchor's char_offsets in the same list). Same-list scoping is load-bearing — refs offsets are local to their parent string, not body-global. Bumps the sidecar's `schema_version` to 1.12.0 on each successful write (since `resolved_to` is an additive 1.12.0 field). `--report-only` / `--vote-only` / `--xref-only` are mutually exclusive selectors for a single pass. `--force` overrides the idempotency gate on all selected passes (re-link populated entries; the xref pass also clears stale `resolved_to` when the new run finds no anchor — making `--force` the canonical "re-resolve under current rules" command). `--dry-run` prints what would change without writing. Schema-revalidates each sidecar before atomic in-place rewrite; an invalid post-link shape is rejected and the file is NOT touched. When S3 env vars are set, modified sidecars re-upload (overwrites the bucket copy). Run **after** `extract` — extract writes the sidecars with `received_in_document: null`, `defers_to: null`, `resolves: []`, `resolved_to: null`; link fills them in.
- Registry-driven backfill: `uv run monitorul-ii backfill <path> [<path> ...] [--kind=issuing_body|ministry|proposed_by|persons|all] [--force] [--dry-run] [--reupload-on-skip] [-j N | --workers N] [--bucket NAME | --no-upload]` — walk `*.extraction.json` sidecars and join curated registries against the schema's `*_normalized` slots and `Speaker.person_id`. v0.1.0 ships **four passes** (default `all` runs every pass; forward-compatible with future registries): `--kind=issuing_body` populates `report_facsimile.body.report.issuing_body_normalized` from the institutional-bodies registry; `--kind=ministry` populates `qr.questions[].addressee.ministry_normalized` + `plenary_*.interpellations[].addressed_to_normalized` from the ministries registry (with institutional fallback); `--kind=proposed_by` populates `plenary_*.agenda_items[].activities[].proposed_by` (Guvern Speaker) on votes whose parent agenda carries an OUG/OG cite or title pattern; `--kind=persons` walks every Speaker dict in the body and populates `Speaker.person_id` from `persons.json` via `normalize_speaker(name_or_raw, context_year=metadata.year)`. Same atomic-write + pre-write schema validation contract as `link`. Idempotent: skips when target slot already holds the same canonical id; mismatches skip with reason unless `--force` overwrites. `--dry-run` prints what would change (with raw value + matched-via tier) and exits without writing. `-j N` / `--workers N` runs the per-sidecar match loop in a `ProcessPoolExecutor` (spawn context, default = CPU count); each worker rebuilds the matcher's lru-cached alias index once (~1-2s startup per worker) and amortizes that cost over its slice. Output appears in completion order, not input order; `-j 1` short-circuits to the serial generator path for deterministic ordering. Single-path workloads also short-circuit (spawning a pool for one task burns startup cost for no gain). Real-world speedup ~2.5× at 200 sidecars / 16 workers — bounded because JSON parse + schema validate + atomic rewrite share the per-sidecar critical path with the matcher itself. **Ctrl+C is graceful with an escape hatch**: workers register `signal.SIG_IGN` for SIGINT (`_worker_ignore_sigint` initializer) so they finish their current sidecar atomically (no `.part` leaks); the parent's `_run_in_parallel` uses `try/finally + shutdown(wait=False, cancel_futures=True)` instead of a `with ProcessPoolExecutor` block (the `with` form's auto-`shutdown(wait=True)` is interruptible by a second Ctrl+C and dumps `Exception ignored in: <generator object>`); and `cmd_backfill`'s KbdInt handler is two-stage — first Ctrl+C prints the "interrupted: …" summary and returns 130, with a `_hard_exit` SIGINT handler installed for the next signal. A second Ctrl+C calls `os._exit(130)` and terminates the process immediately so users who hit a long worker-init phase (20 workers each loading persons.json, ~1-2s) aren't locked. Trade-off on the hard-exit path: orphaned workers may leave `.part` files behind (atomic-rename contract still protects the canonical sidecars; `find pdfs/ -name '*.part' -delete` reaps any leftovers). `--reupload-on-skip` is a precision-targeted repair flag: when set, sidecars that skip with reason `already filled` ALSO re-upload to S3 with `overwrite=True` — closes the historical bucket-staleness gap from pre-overwrite-fix runs that wrote modifications locally but failed to propagate them to S3 (the upload_if_missing head-object gate short-circuited on existing keys). Other skip reasons stay upload-skipped (the local file doesn't carry pass-emitted data, so "stale" doesn't apply); no effect under `--no-upload`. The gate decision lives in `_should_upload_after_backfill(result, *, reupload_on_skip)` so all four passes share identical semantics. **Production sweep**: issuing_body — 34/34 (100%) of R-suffix sidecars with a non-null raw value resolve. Ministry — 92.7% of qr question addressees + 85.6% of meaningful plenary addressees. proposed_by — 10.76% of plenary votes (5330/49556) attributed to Guvern; 554 sidecars touched (post-`agenda.py` v0.2.5 re-baseline). persons — seed-stage (~50 entries) hits the leadership tier (chamber presidents / chairs / PMs / ministers) and the highest-frequency speakers; the long tail closes via `tools/scrape_cdep.py` + `tools/scrape_wikidata.py` + manual resolution against `data/persons_unresolved.jsonl`. Run **after** `extract` — backfill versions are NOT in `extractor_versions` (re-extract clobbers the `*_normalized` slots; re-running `backfill` recovers).
- Persons bootstrap tools (under `tools/`): `aggregate_speakers.py` walks all sidecars and emits `data/speakers_raw.jsonl` + `data/speaker_clusters.jsonl` (one row per name-form-normalized cluster); `scrape_cdep.py` fetches per-legislature deputy lists from cdep.ro (HTML scrape, polite 1-req/sec, retry on 5xx) — **currently unreachable; the live site times out on every legislature**, so cdep is not the primary registry-population path; `scrape_senat.py` is a STUB (senat.ro is a GUID-driven CMS with no scrapeable senator-list endpoint); **`scrape_wikidata_bulk.py`** is the **primary** registry-population tool — paginated SPARQL fetch of every Romanian human (P31=Q5 + P27=Q218) whose Wikidata description contains a politician-shaped keyword (~9,500 entries as of 2026-05). One paginated query per 5000-entry chunk, 5s sleep between pages, 5xx retry with 8s backoff. Output: `data/seed_wikidata_bulk.jsonl` with `{qid, label_en, label_ro, description, birth_date}`. **`merge_wikidata_bulk.py`** dedupes against existing entries (by QID first, then by orderless name-token-set key) and writes new entries to `persons.json` with auto-generated aliases (en label, ro label if different, reversed-token form, ASCII-folded form). New entries arrive with `mandates: []` since Wikidata's P39 data is inconsistently populated for Romanian legislatures; manual / cdep mandate enrichment fills those in. **`enrich_persons_wikidata.py`** is the per-entry lookup variant — used to fix the 31 hallucinated QIDs from the original hand-curated seed (smoke-tested against Wikidata, found ALL 31 wrong → cleared and re-applied via per-name SPARQL lookup with description-keyword + birth-date scoring). **`add_unresolved_speakers.py`** closes the long-tail gap by minting a stub registry entry (`wikidata_qid: null` / `mandates: []`) for every corpus speaker cluster that doesn't already match an existing entry — re-clusters `data/speakers_raw.jsonl` under the matcher's aggressive fold, skips non-canonical labels (`Din sală`, `Guvernul`, …) and junk single-token names, skips clusters whose fold-key OR `normalize_speaker` resolves an existing entry, and mints kebab-case `<surname>-<given>` ids with collision suffixes. **Critical aliasing contract**: stubs only carry the un-peeled raw / name forms as aliases — peeled forms are deliberately not added because they would homonym-collide with canonical Wikidata entries on the matcher's diacritic-folded index (the matcher peels honorifics + titles at lookup time, so peeled aliases are redundant; concrete bug fixed in v0.1.0: a polluted "Domnule Nicolae Văcăroiu" cluster would otherwise add "Nicolae Văcăroiu" as alias, blowing up the canonical `vacaroiu-nicolae` entry's diacritic match). Production sweep: 7,330 fold-keys → 4,414 stubs minted (2,555 already in registry / 110 non-canonical / 251 junk); registry 9,065 → 13,479 entries; bumps single-doc coverage smoke from 99.7% → 99.9% on the 1,526-speaker 2024-01-15 stenogram. Runtime ~8 min on the full corpus (the per-cluster `normalize_speaker` safety-net call dominates; not parallelised because the matcher's lru-cached alias index is single-process). **`merge_cdep_into_persons.py`** handles the (currently dormant) cdep path: dedupes mandates by person, mints kebab-case ids, builds proper-cased aliases. `inspect_speaker.py` shows context excerpts for any unresolved raw (manual long-tail resolution loop). The original `scrape_wikidata.py` is a deprecation marker pointing at `enrich_persons_wikidata.py`. **Bootstrap workflow** (one-time, then idempotent): `scrape_wikidata_bulk` → `merge_wikidata_bulk` populates the registry to ~9,000 entries with 100% QID coverage; `aggregate_speakers` produces the long-tail report; `add_unresolved_speakers` closes the corpus-coverage gap with stubs; `inspect_speaker` + manual edits clean up the remaining ambiguous / mojibake-mangled clusters.

`PROXY_URL` from `.env` (auto-loaded via `python-dotenv`) routes all monitoruloficial.ro traffic through an HTTP/HTTPS proxy. `--proxy` overrides; `--no-proxy` bypasses both. Passwords in the proxy URL are masked in stderr logs.

When the full set of `S3_ENDPOINT` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` / `S3_BUCKET` env vars is present, every PDF is also pushed to S3 (Cloudflare R2 works as the S3 endpoint). Upload is per-file and idempotent: `head_object` first, `upload_file` only if missing. `--no-upload` disables the mirror; `--bucket` overrides `S3_BUCKET`. Object key = local filename, flat. Startup does a `head_bucket` fail-fast. ETags are recorded in the DB.

A SQLite audit log at `data/monitorul.db` (override `--db PATH`, disable `--no-db`) gates whether each day's index POST happens. `days.status='ok'` past days short-circuit the index fetch on resume — including weekends and empty days that have zero Partea II issues. The filesystem and bucket still gate per-PDF skip; the DB doesn't pretend to know whether a file actually exists. `--reverse` walks newest→oldest. `--force` ignores the DB skip; `--rescrape-recent N` re-fetches the last N days regardless of status (today is always re-fetched). See `docs/architecture.md` for the schema and resume contract.

Per-request retries: 3 attempts with backoff `1s → 2s → 4s` for transient errors (5xx, 429, transport). 4xx-not-429 / parse / content-type errors raise immediately. Failures are then classified at the call site: **transient → `status='failed'`** (auto-retried on the next run); **permanent → `status='gone'`** (terminal — content-type mismatch or 4xx-not-429, which mean the server doesn't have the resource as a PDF; not auto-retried, treated like `downloaded`/`uploaded` by the resume gate). `--retry-gone` resets every `gone` row back to `pending` for one-off recovery if the source site restores missing documents. `attempts` is informational.

PDFs land directly in `<out>/<YYYY-MM-DD>_MO-P<part>-<num>-<year>.pdf` (no per-day subdirectory — the date is in the filename so everything sorts chronologically in one folder). Re-runs skip files already on disk; partial downloads write to a `.part` file and are renamed atomically on success. Sha256 + size land in the DB during streaming download (or lazily during the existing-file skip path).

`convert` produces `<basename>.md` next to each `<basename>.pdf` via `pymupdf4llm.to_markdown` plus an MO-specific cleanup pass (strips per-page `MONITORUL OFICIAL...` running headers, image placeholders, standalone page numbers; joins hyphenated word breaks; collapses extra blank lines) and a YAML frontmatter prepend (`issue`, `year`, `part`, `published` from the filename; best-effort `chamber`, `session`, `session_date`, `legislature` parsed from the first ~5 KB of body — graceful fallback if any field can't be detected). Idempotent: skip when `.md` exists & non-empty; `--force` re-converts. MDs mirror to S3 with `Content-Type: text/markdown` (same bucket, flat key). The DB is *not* extended for MD state — filesystem + `head_object` cover idempotency.

Conversion is parallelized via `ThreadPoolExecutor(-j N)`. PyMuPDF releases the GIL during PDF parsing so threads scale on multi-core. `cli.py` sets `OMP_NUM_THREADS=1` + `ORT_INTRA_OP_NUM_THREADS=1` via `setdefault` *before* importing `pymupdf4llm`, otherwise the layout model's ORT session auto-spawns its own intra-op pool that fights the outer workers for cores (8 PDFs measured: 110 s default → 28.7 s with the env vars + `-j 8`, 3.8× speedup). Events fire in completion order (not input order); `on_event` runs in the calling thread to keep S3 uploads serialized without locks. Throughput plateaus around `-j 8` on the 20-core test box. **No GPU path** — `pymupdf-layout` hardcodes one of its two ORT sessions to `CPUExecutionProvider`, so `onnxruntime-gpu` would only accelerate half the work; not worth the ~3 GB install.

`convert` shows progress identically to `fetch`: a live `rich` bar on stderr when isatty (PDF count, %, elapsed, ETA, running converted/skipped/errors + s3 totals), or a `progress: …` heartbeat every `_CONVERT_HEARTBEAT_EVERY` PDFs in pipes. The reporter is a context-manager (`with _ConvertProgressReporter(total, counters) as report`); `report.print(line, err=…)` writes lines above the bar (or to stdout/stderr in heartbeat mode), `report.advance()` ticks the bar and emits heartbeats. Counters are a single mutable dict shared by `cmd_convert`'s closure and the reporter — bumping a counter inside `on_event` is reflected in the next bar redraw. Ctrl+C: `convert_all`'s parallel branch wraps `as_completed` in `try/except KeyboardInterrupt` and calls `ex.shutdown(wait=True, cancel_futures=True)` before re-raising; `cmd_convert` catches the KbdInt and prints `interrupted: converted=… skipped=… errors=… | s3 …` (using the live counters) before returning 130. The `wait=True` is intentional — letting in-flight workers finish their current PDF means no half-written `.md` files and no atexit thread-join race that would otherwise dump a traceback.

`classify` is the type detector — step 1 of the extraction pipeline (see `docs/extraction-schema.md` build order). Pure-regex sweep over each MD's filename suffix + first 10 KB of body, scoring each of the six document types (`plenary_stenogram | plenary_joint_session | committee_synthesis | report_facsimile | question_register | other`). Output is one JSONL row per file to stdout with `{file, top_type, top_score, second_type, second_score, ambiguous, all_scores, matched_signals}`; summary counts to stderr. `--outliers` filters to docs that landed in `other` or are flagged ambiguous — the latter excludes structural co-evidence (joint_session ⊃ stenogram, report received in joint session) via `_COMPATIBLE_RUNNERS_UP`. On the 2300+ doc corpus the sweep runs in <2 s and (as of v1.3.0 schema rules) lands every document into a typed bucket with zero residual outliers.

`extract` is the structuring step — step 2 / step 1.5 of the extraction pipeline (`docs/extraction-schema.md` build order, revised). Reads each MD, splits the YAML frontmatter into `metadata`, classifies it, dispatches to `EXTRACTORS[doc_type]`, merges the extractor's record claims with the shared `claim_shared_boilerplate` output, computes coverage, calls `assign_identity` to mint per-record `id` / `content_fingerprint` / `slug` (reading any prior sidecar to enforce slug-once), builds the envelope (carrying per-component `extractor_versions`: `boilerplate / coverage / identity / references / speakers / topics / <doc_type>` + an `extraction.identity` block whose `record_id` mirrors `document_id`), validates the full sidecar against `extraction_schema.json` strictly, and writes `<basename>.extraction.json` atomically next to the MD. **Version-aware idempotency**: an existing sidecar is reused iff its `schema_version` AND every key in `extractor_versions` matches the runtime; mismatch re-extracts automatically. `--force` overrides. `--identity-only` opens an alternative fast path: read the existing sidecar's body, run `assign_identity` over it, bump only `extractor_versions.identity` + `schema_version`, rewrite atomically. This avoids re-running per-type extractors during the schema-1.13.0 backfill (~30 minutes saved on the 5552-doc corpus). Schema validation runs **pre-write**: a violation never lands a malformed sidecar on disk; the rejected dict is dumped to `<basename>.rejected.json` for inspection. Source-span coordinate system locked: 0-indexed half-open char offsets into the **body text** (post-frontmatter); 1-indexed inclusive line numbers; `content_sha` = sha256 of body bytes truncated to 12 hex chars. Coverage is **diagnostic-only** — `--coverage-below MARGIN` emits JSONL rows to stdout for the discovery loop, but never blocks writes. v0.1 ships all six per-type extractors: `question_register` (53-doc cohort, p50 coverage 99.7%), `plenary_stenogram` (2240-doc cohort), `plenary_joint_session` (~50-doc cohort), `committee_synthesis` (976-doc cohort, mean 0.997, median 1.000, p25 0.999, min 0.886), and `report_facsimile` (52-doc cohort, mean 0.999, median 0.999, min 0.970, zero errors). Coverage targets per Q9 are **discovery margin 0.85**, **test fixture floor 0.80**, **mean target 0.90 documented (ungated)**. Five hand-picked plenary fixtures span modern joint, modern Camera, modern Senat, mid-2017, and older 2013 layouts; four committee_synthesis fixtures span 2008/2018/2022/2025 (narrative + tabular + mojibake + pandemic-era); four report_facsimile fixtures span 2014 image-only CSAT, 2014 SRI, 2017 Consiliul Legislativ, 2024 ANCOM (rich modern body); suite enforces ≥0.80 per fixture. When `S3_*` env vars are set, sidecars mirror with `Content-Type: application/json`. Sequential by design — regex sweeps hold the GIL, parallelism would buy nothing.

(A `.ruff_cache` is present; no committed config, so ruff defaults apply.)

**After each code change, run `uv run ruff format` and `uv run ruff check --fix` before reporting the task complete.**

**Tests are mandatory for every new feature, in the same change. Non-negotiable.** A "feature" here means any new function, CLI flag, regex, parser branch, DB column, state-transition, or behavior change. The bar is:

- **New pure function** → at least one happy-path test plus one rejection / edge case (empty input, malformed input, boundary).
- **New CLI flag** → one test that exercises the flag's effect (parser-level via `_build_parser` or behavior-level via the helper it toggles). Don't test argparse itself; test the branch it switches on.
- **New regex / parser branch** → one positive sample, one negative sample, and one for any quirk you encoded (e.g. legacy glyph mapping, suffix tolerance).
- **New DB state transition** → one test that drives the transition and asserts the row, plus one for the idempotency / re-entry case if the transition is callable twice.
- **New scraper / converter behavior** → drive `scrape_day` or `convert_all` end-to-end with `httpx.MockTransport` / `monkeypatch.setattr(converter, "convert_pdf", ...)` so the orchestration layer is covered, not just the leaf function.

Tests live in `tests/` mirroring `src/monitorul_ii/` (`test_<module>.py`). `tests/conftest.py` exposes a `db` fixture (`DB(tmp_path/"audit.db")`). **Do not** add tests that touch the network, real S3, or real PDFs — every external boundary has a stub already; use it. **Run `uv run pytest` before reporting the task complete; the suite must be green.**

**If a code change breaks tests, fix the tests in the same change — don't leave a red suite.** When tests fail because the production code's contract changed (renamed paths, refactored APIs, removed helpers), update the tests to match the new contract; don't revert the code or skip the tests. Only treat a test failure as a real bug to fix in production code when the test is asserting still-intended behavior.

**Document every new feature, in the same change. Non-negotiable.** A feature is shipped only when *all three* docs reflect it:

- `README.md` — user-facing prose. Every CLI flag must be described in prose (not just shown in an example), including its semantics, default, and any non-obvious interaction with other flags or env vars. If you added a flag, search README to confirm its name appears in a sentence, not only inside a code fence.
- `CLAUDE.md` (this file) — agent-facing scannable summary. The "Commands" section's CLI signature must include the new flag; the prose paragraph for the relevant subcommand must mention any new behavior, default, or dep.
- `docs/architecture.md` — deep mechanics: *why* the flag exists, what tradeoffs it encodes, what was tried and rejected, measured numbers if relevant.

"Meaningful" = a new CLI flag, a new behavior or default, a new module, a new external dependency, a new env-var the CLI reads or sets, a new failure mode, or anything a future user/agent would otherwise have to read the diff to discover. Touching `pyproject.toml` `[project.dependencies]` always counts.

**Keep CLAUDE.md scannable** — push detailed mechanics into `docs/architecture.md` and link from here. CLAUDE.md is the index; architecture.md is the manual.

**Self-check before reporting the task complete:**

1. `uv run pytest` is green and exercises the new code path (don't trust pre-existing coverage).
2. `uv run ruff format` and `uv run ruff check --fix` clean.
3. For each new flag, `grep -n '<flag-name>' README.md CLAUDE.md docs/architecture.md` shows hits in all three. If any miss, write the missing doc *now*, not "as a follow-up".

## uv-on-snap quirk

`uv` installed via snap buffers stdout when there is no tty, so `uv run <cmd>` may appear silent in non-interactive shells. Pipe through `cat` (e.g. `uv run monitorul-ii --help | cat`) or invoke the venv binary directly (`.venv/bin/monitorul-ii ...`) when you need to see output.
