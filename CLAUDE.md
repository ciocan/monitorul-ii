## Layout

- `src/monitorul_ii/scraper.py` — pure functions: `fetch_index`, `parse_issues`, `download_pdf`, `scrape_day`, plus `_with_retry`. Sha256 + size are computed in the streaming download. No CLI concerns.
- `src/monitorul_ii/converter.py` — pure functions: `parse_filename`, `enrich_meta`, `clean_markdown`, `convert_pdf`, `convert_all`, `collect_pdfs`. Wraps `pymupdf4llm.to_markdown` and applies an MO-specific cleanup pass + YAML frontmatter prepend. No CLI concerns.
- `scripts/detect_scanned.py` — one-off OCR-triage diagnostic (NOT wired into the pipeline). Probes every PDF in `pdfs/` in a child subprocess (PyMuPDF can SIGSEGV on malformed image-only PDFs and a thread crash takes the whole process down — subprocess-per-PDF + a JSONL state file at `/tmp/detect_scanned_state.jsonl` makes runs crash-resumable), then classifies each via `avg_chars_per_page` + `image_pages_pct` (per-page `chars < 50` doesn't work — every MO PDF leaks 80–150 chars/page from headers/page numbers/footer running titles even on fully-scanned pages, and 0 of 5552 PDFs land below the per-page floor). Tiers: `ocr_required` (avg<200 AND img>=50%, 9 PDFs) / `ocr_recommended` (avg<500 AND img>=20%, 3 PDFs) / `hybrid` (img>=50% AND avg<2000, 19 PDFs — mostly tiny 2-page cover-sheet+image inserts) / `text_ok` (5521). CSV at `scanned_candidates.csv` (repo root). Use `.venv/bin/python scripts/detect_scanned.py` for full sweep, `--rebuild` to regenerate the CSV from the JSONL cache without re-probing. Largest OCR candidate: `2011-06-10_MO-PII-71Bis-2011.pdf` (3578 pages, 344 MB, 99.5% image pages). See `docs/architecture.md` § "OCR triage" for the threshold rationale + corpus distribution. Routing the 12 OCR-tier PDFs through Mistral OCR (or similar) is a deferred workstream.
- `src/monitorul_ii/classifier.py` — pure functions: `parse_issue_suffix`, `classify`, `classify_file`, `collect_mds`, plus `ClassifyResult` (with `is_ambiguous(threshold)`). Detection rules from `docs/extraction-schema.md` build-order step 1: filename suffix (`c`/`R`) + body markers (`(STENOGRAMA)`, `DEZBATERI PARLAMENTARE`, `ȘEDINȚE COMUNE …`, `(RAPOARTE DE ACTIVITATE)`, `LISTA ÎNTREBĂRILOR ADRESATE`, `SINTEZA LUCRĂRILOR COMISIILOR`). Reads only the first `HEADER_WINDOW_BYTES=10_000` of each MD. `_COMPATIBLE_RUNNERS_UP` suppresses "ambiguous" flagging when the runner-up is structurally implied by the winner (joint_session ⊃ stenogram; report_facsimile is received in joint/single sessions). No CLI concerns.

- `src/monitorul_ii/extraction/enrichments/discourse.py` — **discourse-analysis enrichment producer (v0.1.0)**: `analyze_sidecar(sidecar_path, *, openrouter_url, api_key, model, force, write, dry_run, retry_on_error, max_words, max_tokens, budget_remaining_usd, client, prompts) -> AnalyzeResult` walks every substantive speech (speech-type + canonical-speaker + `len(text) ≥ MIN_TEXT_CHARS=100` + word-count ≤ `--max-words` default 800) and runs the four-prompt LLM pipeline Hawkins → voice (conditional) → DQI → V-Party against OpenRouter (`POST /chat/completions`, OpenAI-compatible). Default model `google/gemini-3.1-flash-lite` (the calibration-picked candidate per `docs/discourse-pilot-baseline-2026-05.md` § 8). Strict `json_schema` response_format is attempted first with an automatic fallback to `json_object` on Gemini's well-known schema-rejection (`additionalProperties: false` / `$schema` / `$id` are all rejected); `parse_and_validate(...)` runs `json.loads` with a `json-repair` fallback for the unescaped-ASCII-quote-inside-Romanian-typography failure mode. Per-speech outputs persist as `<basename>.discourse.flash-lite.v0_1.json` next to the sidecar (`DISCOURSE_NAMESPACE = "discourse"` = the indexer dict key, matches the ES `enrichments.discourse` mapping; `DISCOURSE_PRODUCER = "flash-lite"` = the model-class identifier; `DISCOURSE_VERSION = "0_1"` = filename version). The loader's existing regex (`<basename>.<producer>(.<model>)?.v<version>.json`) parses the file as `producer="discourse"` automatically — no loader changes needed. **Idempotency**: each entry stores a `text_fingerprint` (12-char sha256 of NFC + whitespace-collapsed speech text); on re-run, fingerprint-matched entries reuse the existing payload verbatim (no API call, no file rewrite). Mismatched fingerprints trigger re-coding for that record only. The producer pins prompt versions `PROMPT_VERSIONS = {"hawkins": "v1", "voice": "v1", "dqi": "v1", "vparty": "v2"}` and stamps them on every entry's `_meta.prompt_versions` so a future prompt bump invalidates payloads via `--force`. **Voice conditional**: the voice classifier only runs when Hawkins emits at least one marker — if Hawkins says "no populist markers" voice has nothing to attribute. DQI and V-Party are independent classifiers and always run; sequential at v0.1 for simplicity, v0.2 may parallelise. **Typography-tolerant evidence-text matching (v0.1.0+)**: Hawkins / DQI markers carry `evidence.text` strings the model claims are verbatim quotes from the speech. The producer recovers byte-correct char offsets via `find_text_offsets_tolerant(speech, fragment)` — strict `str.find` first, then a normalised search that folds NFC + lowercase + whitespace runs + Romanian typographic quotes (`„ " " « » → "`, `' ' ‚ ‛ → '`) + unicode dashes (`‐ ‑ ‒ – — ― → -`) + ellipsis (`… → ...`). The offset map projects the normalised match position back to byte-correct ranges in the original speech. When even tolerant matching fails (real paraphrase: added/removed words), the marker is STILL forwarded to the voice classifier WITHOUT `char_range` — voice has `marker_text` and the voice prompt explicitly says hints are signals not commitments. Pre-fix the strict matcher dropped paraphrased markers, and a marker-list of all-paraphrased entries returned `""` causing voice to silently skip and the entry to land in the run's `failed` bucket; corpus smoke surfaced ~85/89 voice-skip-with-markers failures per 700 records (~12%) on Flash-Lite output. Post-fix the failure mode is closed. The same `find_text_offsets_tolerant` is now also called at INDEX TIME by `denormalize.py` so each marker's `evidence.char_range` lands in `mo-speeches.enrichments.discourse.{framework}.markers[].evidence.char_range` — the web app slices `speech.text` directly with no client-side typography fold (see `denormalize.py` paragraph above). **Schema-aware salvage in `parse_and_validate` (v0.1.0+)**: when strict `jsonschema.validate` rejects an output, two salvage passes run before declaring failure, in order. (1) `_strip_unknown_properties` recursively walks the (object, schema) pair and strips keys not declared in `properties` when the schema sets `additionalProperties: false` — closes the DQI drift modes `respect_for_constructive_politics` (hybrid name conflating `respect_for_*` and `constructive_politics`), `text_2` / `text_3` evidence keys, and similar over-emission patterns. Runs FIRST so a marker with one extra evidence key gets cleaned up rather than dropped wholesale. (2) `_filter_invalid_markers` (generalised from the earlier `_filter_unknown_marker_kinds`) instantiates a `Draft202012Validator` over the schema's `markers[].items` shape and drops every marker that fails per-item validation — closes bad-enum-kind values (voice-classifier values like `quoted` leaking into Hawkins / V-Party), missing required fields inside markers (DQI sometimes omits `preliminary_voice` or `rationale_short`), wrong-typed sub-fields (model collapses one nesting level and emits `evidence: "string"` instead of `evidence: {text: "string"}`), and stray non-dict marker entries. Both passes are conservative (only DROP things; never invent missing required fields), so they're a strict improvement: a record that pre-fix would land in `failed` now lands clean with `repaired=1` (the existing telemetry counter conflates json-repair and schema-repair recoveries; the operator just sees a "self-heal happened" signal). Smoke test on the 8 real failed records from the production sweep recovered 6/8 (75%). **Token-cap bump (v0.1.0+)**: `DEFAULT_MAX_TOKENS` 16384 → 32768. Sized against the production token-output distribution (45,189 calls: p50=1488, p95=2352, p99=2979, max=18493 — bimodal with 99% finishing under 3K and a tiny truncation tail at the cap). The previous 16K cap turned the runaway-DQI-markers tail into truncated `'rationale' is a required property` failures because schemas list `rationale` near the end and runaway `markers[]` exhausted the budget before reaching it. Cost-neutral on the 99% path (model emits what it needs, not the cap; cost is per-token-actually-output). **Terseness-on-retry (v0.1.0+)**: `_is_truncation_failure(call, max_tokens)` detects truncation as `error == "schema_invalid"` AND `"is a required property"` in the message AND `tokens_out >= 95% of max_tokens`. When this fires on the previous attempt, `_run_one_prompt` appends `_TERSENESS_RETRY_SUFFIX` to the retry's user prompt — an explicit "MAX 6 markers, MAX 4 sentences for rationale" instruction that breaks the model-degenerate state on heavy-rhetoric short speeches (104 words of personal attack with sarcasm tripping the model into one-marker-per-phrase runaway). Re-uses the existing `--retry-on-error` budget (no extra HTTP call beyond what the operator already authorised); zero cost on the success path because terseness is only injected when the previous attempt's failure shape matches the heuristic. **Validation gate on result-store (v0.1.0+)**: `_run_pipeline_for_speech` now requires `hawkins_call.output AND not hawkins_call.error` (and same for voice / dqi / vparty) before storing the output in `results[...]`. Pre-fix, even schema-invalid outputs got stored, and the model's occasional emission of `markers` as a string instead of an array crashed the entire sidecar with `AttributeError: 'str' object has no attribute 'get'` when `build_prompt_for_voice` iterated the string character-by-character. The gate rejects the bogus shape at the source; voice cleanly skips (no markers to attribute); DQI / V-Party still run independently; the affected record lands in `failed` with the schema_invalid surfaced to the operator while the rest of the sidecar continues unblocked. `build_prompt_for_voice` also got a defensive `isinstance(m, dict)` per-marker guard for any future caller that might pass malformed lists. The combined fixes (matcher + salvage + cap bump + terseness retry + validation gate) reduce the producer's failure rate from ~12% pre-fix to under ~0.005% on the residual; the residual is genuine model truncation that even terseness retry can't recover (rare, ~1 record per 19,200 in expected production scale). **Non-canonical speakers** (`<chair narration>` / `Din sală` / `Voci` / `Guvernul` / `Aplauze` / `Rumoare`) skip coding entirely — the rubrics only grade individual speakers. **Long-tail handling (v0.1)**: speeches above `--max-words` (default 800) skip with reason `text_too_long` (the long-tail v0.2 task is chunked coding via `record_id#chunk-N`). **Cost / budget**: `OPENROUTER_FLASH_LITE_INPUT_RATE_USD = $0.10/M` + `OPENROUTER_FLASH_LITE_OUTPUT_RATE_USD = $0.40/M` (conservative bounds; tunable as module constants). `analyze_sidecar(...)` accepts `budget_remaining_usd: float | None`; when the cumulative-spend estimate hits the cap, the in-flight sidecar finishes atomically and the producer returns `action="budget-exhausted"`. **Error handling**: per-prompt failures don't abort the sidecar — the entry is persisted with `_meta.errors[]` and the affected framework's payload is null. `analyze_all(...)` is the iterator entry point with shared `httpx.Client` for connection reuse + cumulative-budget tracking across sidecars. `healthcheck(openrouter_url, api_key)` is a 10-second `GET /models` probe used by the CLI to fail fast on a misconfigured endpoint or bad key. `DEFAULT_MAX_WORDS = 800`, `DEFAULT_MAX_TOKENS = 16384`, `DEFAULT_OPENROUTER_URL = "https://openrouter.ai/api/v1"`. `__init__.py` re-exports the public surface so `from monitorul_ii.extraction.enrichments import discourse` works as one-stop.

## How the scraper talks to the site

There is no documented API. Reverse-engineered from the e-monitor page:

- **Index endpoint**: `POST https://monitoruloficial.ro/ramo_customs/emonitor/get_mo.php` with form body `today=YYYY-MM-DD` and a `Referer: https://monitoruloficial.ro/e-monitor/` header. Returns an HTML fragment — one `<div class="card-body">` per Partea, with `<a href="/Monitorul-Oficial--P<part>--<num>--<year>.html">` links.
- **PDF**: GET that `.html` URL — the response body **is** the PDF (`Content-Type: application/pdf`). The `.html` extension is misleading.
- Issue numbers can carry suffixes (`358Bis`, `12c`) — the parser regex accepts `[0-9A-Za-z]+`.
- Empty days (weekends, no Partea II that day) return zero issues; not an error.

## Commands

- Install / sync deps: `uv sync`
- Fetch PDFs: `uv run monitorul-ii fetch <YYYY-MM-DD> [--until YYYY-MM-DD] [--out DIR] [--part II] [--delay 0.5] [--proxy URL | --no-proxy] [--bucket NAME | --no-upload] [--db PATH | --no-db] [--reverse] [--force] [--rescrape-recent N] [--retry-gone]`
- Convert PDFs to markdown: `uv run monitorul-ii convert <path> [<path> ...] [--force] [-j N | --workers N] [--reverse] [--bucket NAME | --no-upload]` — paths are files or directories; directories are globbed `*.pdf` (non-recursive). Default `-j` is `os.cpu_count()`; conversions run in a `ThreadPoolExecutor`. `--reverse` flips the final PDF list (newest→oldest given the date-prefixed filenames) — same semantics as `fetch --reverse`.
- Classify converted MDs: `uv run monitorul-ii classify <path> [<path> ...] [--outliers] [--ambiguity-threshold MARGIN] [--reverse]` — sweep MDs and emit one JSONL row per file to stdout (`top_type`, `top_score`, `second_type`, `second_score`, `ambiguous`, `all_scores`, `matched_signals`). `--outliers` filters to docs that classified as `other` or are ambiguous (top-vs-second margin below `--ambiguity-threshold`, default 0.2) — those are the unknown unknowns the schema-discovery loop wants to inspect. `--reverse` walks newest→oldest like the other subcommands.
- Extract structured JSON sidecars: `uv run monitorul-ii extract <path> [<path> ...] [--force] [--type TYPE] [--coverage-below MARGIN] [--reverse] [--identity-only] [--bucket NAME | --no-upload]` — dispatch each MD to its per-type extractor and write `<basename>.extraction.json` next to it. `--force` overrides the version-aware idempotency gate; `--type` overrides the classifier on a per-run basis (sparingly); `--coverage-below MARGIN` adds a JSONL outlier line to stdout for each doc whose `claimed_pct < MARGIN`; `--reverse` walks newest→oldest; `--identity-only` is the schema-1.13.0 backfill fast path — skips the per-type extractor and re-runs only `assign_identity` against the existing sidecar's body, bumping `extractor_versions.identity` and `schema_version` to 1.13.0. v0.1 ships extractors for all six document types — `question_register`, `plenary_stenogram`, `plenary_joint_session`, `committee_synthesis`, and `report_facsimile` (100% coverage of the typed corpus). The skip-with-reason path remains in place for any future type that ships a classifier rule before its extractor lands.
- Linker: `uv run monitorul-ii link <path> [<path> ...] [--force] [--dry-run] [--report-only | --vote-only | --xref-only] [--bucket NAME | --no-upload]` — walk `*.extraction.json` sidecars and run **three passes** by default. Pass 1 (report→session, cross-doc) builds an index of `plenary_joint_session` + `plenary_stenogram` sidecars by `metadata.session_date` and fills each `report_facsimile` sidecar's `received_at.received_in_document` with the matching `document_id`. Pass 2 (vote-pair, cross-doc, linker v0.2.0+) builds a vote index keyed by **bill cite only** (`f"bill:{number}/{year}"`, with `motion:{kind}:{title-hash}` for motion-class votes carrying a quoted title ≥12 chars; other ref types and agenda-title hashes intentionally excluded — see linker.py module docstring for the false-positive analysis), pairs deferred votes (`outcome=deferred`) with their resolvers in subsequent stenograms within the 60-day window (`DEFERRAL_WINDOW_DAYS=60`), and writes `defers_to` (forward link) on the deferring vote + `resolves[]` (back-link, list of origin document_ids) on the resolver. Multi-deferral chains: A→B→C produces `A.defers_to=B`, `B.defers_to=C`, `C.resolves=[A, B]` (chain reversal). Pass 3 (cross-reference, intra-doc, xref_linker v0.1.0+) walks each plenary sidecar's reference lists and resolves bare `art. N` unknowns to the nearest preceding non-unknown reference IN THE SAME LIST (`primary_references[]` / `references_mentioned[]`); writes `unknown.resolved_to.char_offsets` (a pointer at the anchor's char_offsets in the same list). Same-list scoping is load-bearing — refs offsets are local to their parent string, not body-global. Bumps the sidecar's `schema_version` to 1.12.0 on each successful write (since `resolved_to` is an additive 1.12.0 field). `--report-only` / `--vote-only` / `--xref-only` are mutually exclusive selectors for a single pass. `--force` overrides the idempotency gate on all selected passes (re-link populated entries; the xref pass also clears stale `resolved_to` when the new run finds no anchor — making `--force` the canonical "re-resolve under current rules" command). `--dry-run` prints what would change without writing. Schema-revalidates each sidecar before atomic in-place rewrite; an invalid post-link shape is rejected and the file is NOT touched. When S3 env vars are set, modified sidecars re-upload (overwrites the bucket copy). Run **after** `extract` — extract writes the sidecars with `received_in_document: null`, `defers_to: null`, `resolves: []`, `resolved_to: null`; link fills them in.
- Registry-driven backfill: `uv run monitorul-ii backfill <path> [<path> ...] [--kind=issuing_body|ministry|proposed_by|persons|all] [--force] [--dry-run] [--reupload-on-skip] [-j N | --workers N] [--bucket NAME | --no-upload]` — walk `*.extraction.json` sidecars and join curated registries against the schema's `*_normalized` slots and `Speaker.person_id`. v0.1.0 ships **four passes** (default `all` runs every pass; forward-compatible with future registries): `--kind=issuing_body` populates `report_facsimile.body.report.issuing_body_normalized` from the institutional-bodies registry; `--kind=ministry` populates `qr.questions[].addressee.ministry_normalized` + `plenary_*.interpellations[].addressed_to_normalized` from the ministries registry (with institutional fallback); `--kind=proposed_by` populates `plenary_*.agenda_items[].activities[].proposed_by` (Guvern Speaker) on votes whose parent agenda carries an OUG/OG cite or title pattern; `--kind=persons` walks every Speaker dict in the body and populates `Speaker.person_id` from `persons.json` via `normalize_speaker(name_or_raw, context_year=metadata.year)`. Same atomic-write + pre-write schema validation contract as `link`. Idempotent: skips when target slot already holds the same canonical id; mismatches skip with reason unless `--force` overwrites. **`--force` on the persons pass also clears stale fills** when the matcher now returns no match for a speaker raw that an earlier matcher version resolved (e.g. recovery path after the per-token fuzzy tier rejects an old joined-Lev≤2 false positive); without `--force` the stale value is preserved so manual operator-set ids aren't silently dropped. `--dry-run` prints what would change (with raw value + matched-via tier) and exits without writing. `-j N` / `--workers N` runs the per-sidecar match loop in a `ProcessPoolExecutor` (spawn context, default = CPU count); each worker rebuilds the matcher's lru-cached alias index once (~1-2s startup per worker) and amortizes that cost over its slice. Output appears in completion order, not input order; `-j 1` short-circuits to the serial generator path for deterministic ordering. Single-path workloads also short-circuit (spawning a pool for one task burns startup cost for no gain). Real-world speedup ~2.5× at 200 sidecars / 16 workers — bounded because JSON parse + schema validate + atomic rewrite share the per-sidecar critical path with the matcher itself. **Ctrl+C is graceful with an escape hatch**: workers register `signal.SIG_IGN` for SIGINT (`_worker_ignore_sigint` initializer) so they finish their current sidecar atomically (no `.part` leaks); the parent's `_run_in_parallel` uses `try/finally + shutdown(wait=False, cancel_futures=True)` instead of a `with ProcessPoolExecutor` block (the `with` form's auto-`shutdown(wait=True)` is interruptible by a second Ctrl+C and dumps `Exception ignored in: <generator object>`); and `cmd_backfill`'s KbdInt handler is two-stage — first Ctrl+C prints the "interrupted: …" summary and returns 130, with a `_hard_exit` SIGINT handler installed for the next signal. A second Ctrl+C calls `os._exit(130)` and terminates the process immediately so users who hit a long worker-init phase (20 workers each loading persons.json, ~1-2s) aren't locked. Trade-off on the hard-exit path: orphaned workers may leave `.part` files behind (atomic-rename contract still protects the canonical sidecars; `find pdfs/ -name '*.part' -delete` reaps any leftovers). `--reupload-on-skip` is a precision-targeted repair flag: when set, sidecars that skip with reason `already filled` ALSO re-upload to S3 with `overwrite=True` — closes the historical bucket-staleness gap from pre-overwrite-fix runs that wrote modifications locally but failed to propagate them to S3 (the upload_if_missing head-object gate short-circuited on existing keys). Other skip reasons stay upload-skipped (the local file doesn't carry pass-emitted data, so "stale" doesn't apply); no effect under `--no-upload`. The gate decision lives in `_should_upload_after_backfill(result, *, reupload_on_skip)` so all four passes share identical semantics. **Production sweep**: issuing_body — 34/34 (100%) of R-suffix sidecars with a non-null raw value resolve. Ministry — 92.7% of qr question addressees + 85.6% of meaningful plenary addressees. proposed_by — 10.76% of plenary votes (5330/49556) attributed to Guvern; 554 sidecars touched (post-`agenda.py` v0.2.5 re-baseline). persons — seed-stage (~50 entries) hits the leadership tier (chamber presidents / chairs / PMs / ministers) and the highest-frequency speakers; the long tail closes via `tools/scrape_cdep.py` + `tools/scrape_wikidata.py` + manual resolution against `data/persons_unresolved.jsonl`. Run **after** `extract` — backfill versions are NOT in `extractor_versions` (re-extract clobbers the `*_normalized` slots; re-running `backfill` recovers).

- Discourse-analysis producer: `uv run monitorul-ii analyze <path> [<path> ...] [--force] [--dry-run] [--limit N] [--reverse] [--openrouter-url URL] [--retry-on-error N] [--max-words N] [--budget-usd N] [-j N | --workers N] [--bucket NAME | --no-upload]` — walk `*.extraction.json` sidecars and run the four-prompt LLM pipeline (Hawkins populism → voice attribution → DQI deliberative quality → V-Party + V-Dem anti-pluralism) over every substantive speech (`text_length ≥ MIN_TEXT_CHARS=100`, canonical-speaker via `NON_CANONICAL_SPEAKERS` denylist, word count ≤ `--max-words` default 800). DQI and V-Party are independent classifiers (no marker dependency on Hawkins) but kept sequential at v0.1 for simplicity; v0.2 may parallelise. **OpenRouter adapter**: direct httpx `POST /chat/completions` with `response_format: json_schema` strict mode, automatic fallback to `json_object` on 400 BadRequest matching the schema-rejection vocabulary (Gemini's well-known limitation: rejects `$schema` / `$id` / `additionalProperties: false` / `anyOf`). The schema is inlined in the prompt body so semantic enforcement happens via the prompt + downstream `parse_and_validate` (json.loads + json-repair fallback for unescaped-ASCII-quotes-inside-Romanian-typography). **Idempotency**: each entry stores a `text_fingerprint` (12-char sha256 of NFC + whitespace-collapsed speech text); on re-run, fingerprint-matched entries reuse the existing payload verbatim — no API call, no file rewrite. Mismatched fingerprints trigger re-coding for that record only. **Pinned prompt versions** stamped on every entry's `_meta.prompt_versions`: `hawkins=v1, voice=v1, dqi=v1, vparty=v2`. `--force` overrides the fingerprint match (use after a prompt-version bump); `--dry-run` walks records and reports counts without contacting OpenRouter or writing files. `--limit N` caps sidecars processed; `--reverse` walks newest→oldest. `--openrouter-url URL` overrides the default `https://openrouter.ai/api/v1` (also reads `OPENROUTER_URL` env var); the CLI smoke-tests `GET /models` before walking the sidecar list so a misconfigured endpoint or bad API key fails fast with exit 2. `--retry-on-error N` is the per-call retry budget (default 1; exponential backoff 1, 2, 4, 8s capped at 8s). `--max-words N` skips long-tail speeches above the threshold (default 800; v0.2 will introduce chunked coding with `record_id#chunk-N`). `--budget-usd N` is a soft cap on cumulative estimated spend; per-call cost = `tokens_in × $0.10/M + tokens_out × $0.40/M` (Flash-Lite conservative bounds, constants in `discourse.py`). When the cap is hit, the in-flight sidecar finishes atomically and the producer exits cleanly with `action="budget-exhausted"` (exit 0); resume by re-running — fingerprint-match short-circuits at zero cost. `-j N` dispatches via `ThreadPoolExecutor` (default 1; threads, not processes — calls are network-bound, GIL-friendly via httpx; shared `httpx.Client` whose urllib3 pool is thread-safe). When S3 is configured, modified discourse files mirror with `Content-Type: application/json` and `overwrite=True`. **Cost / time**: Flash-Lite calibration baseline ~$0.005 / speech across 4 prompts; ~19,200 substantive speeches in the 40-month March 2023 → present window cost ~$94 at `-j 16` over ~3 hrs wall-clock (within the $100 cap). Reads `OPENROUTER_API_KEY` from environment / `.env`. Run **after** `extract` / `link` / `backfill` / `embed`, **before** `index`.

- Elasticsearch indexer: `uv run monitorul-ii index <path> [<path> ...] [--force] [--dry-run] [--reverse] [--target=INDEX] [--mirror] [--rebuild] [--grain=GRAIN ...] [--db PATH] [--index-generation LABEL] [-j N | --workers N] [--include-persons] [--errors-log PATH]` — walk `*.extraction.json` sidecars, denormalise across the nine grains (per Q5 of `docs/elasticsearch-indexing.md`), bulk-upsert via per-grain write aliases (`<grain>-write`), track state in the SQLite `es_indexed` table, and `delete_by_query` orphans per the diff between the previous run's `child_record_ids` and the current run's. **Idempotency triple** `(sidecar_content_sha, enrichment_fingerprint, index_generation)` — all three match → skip; applies to the sequential and `-j N` parallel paths alike (parallel output is in completion order regardless, but dispatch order respects `--reverse`). `--target=<index>` redirects writes for that grain prefix to a specific blue-green generation (`mo-speeches-20260615-v2`); `--mirror` keeps the live `<grain>-write` alias in sync during catch-up by writing to BOTH targets per bulk action. `--rebuild` is the bootstrap-rebuild convenience flag (implies `--force`; demands `--target` — the handler errors out with exit 2 otherwise). `--grain` restricts projection to a subset (repeatable). `--index-generation` is the third leg of the idempotency triple (default `live`); set when running `--target` so the state row tracks the right generation independently. **Enrichment merge**: `<basename>.<producer>.v<version>.json` files alongside each sidecar are globbed + version-selected (configured-live wins; default highest-on-disk) and merged by `record_id`; entries with stale `_meta.source_sidecar_content_sha` are dropped (the producer ran against an older sidecar body). The journal `<basename>.journal.jsonl` appends as `record_id["journal"][producer]`. INDEXER_VERSION = `0.2.0`. **Parallelism**: `-j N` / `--workers N` (default 1) dispatches to `index_all_parallel(...)` — `ThreadPoolExecutor` with per-thread `DB(db_path)` connections (SQLite forbids cross-thread sharing; WAL mode handles concurrent reads + serialised writes fine at this rate); single shared `Elasticsearch` client (urllib3 connection pool is thread-safe). Threads (not processes) because the bottleneck is ES network round-trips, both of which release the GIL via urllib3 — process pool would pay serialisation cost per task and re-construct the ES client + DB connection on every spawn. Output yields in completion order (not input order) when N > 1; falls back to sequential when `N <= 1` or `len(paths) == 1`. 20-core box: `-j 16` lifts ~92 sidecars/min (sequential, ~60 min on 5552-doc corpus) to ~600-900/min (~6-10× speedup, bounded by ES bulk-throughput ceiling). **Transient-failure resilience**: the ES client is built with `max_retries=3, retry_on_timeout=True, request_timeout=30s` so connection-timeout / network-blip failures auto-retry at the transport layer; `helpers.bulk` is invoked with `max_retries=3, initial_backoff=2, max_backoff=8` so cluster-side `429 es_rejected_execution_exception` (bulk-queue saturation under high `-j N`) auto-retries with exponential backoff. Bulk upserts are idempotent (keyed on `_id`), so retries are safe. Pre-fix: a `--force -j 16` run on the 5,556-doc corpus surfaced 3 transient bulk-error failures with no auto-recovery; post-fix the same shape of transient is absorbed by the retry layer. **`--errors-log PATH`**: when any sidecar fails, the CLI appends one JSON line per failure to `PATH` (`{ts, document_id, sidecar_path, errors[]}`); lazy-create so a clean run leaves no empty file. If the flag is omitted **and** errors fire, the CLI auto-picks `data/index-runs/index-errors-<ISO-timestamp>.jsonl` (mirrors the `data/embed-runs/` / `data/analyze-runs/` / `data/catchup-reports/` convention) — closes the prior visibility gap where the rich progress bar's stderr Console interleaved ERR lines with thousands of `ok` lines and the failures scrolled past the terminal buffer in a long-running parallel sweep. Final summary surfaces the path (`errors-log=...`); operator can then `jq` the file for the offending sidecars and re-run them serially. **`--include-persons`**: optional flag that also projects the curated `persons.json` registry into `mo-persons` after the sidecar loop finishes via `index_persons_with_state(es, db, persons, ...)` — sister to `index_one(...)` with its own idempotency check (sentinel state row keyed `__persons_registry__`, content-hash of the canonical-JSON-serialised registry). Persons aren't sidecar-derived (Q4 — they live in `src/monitorul_ii/registries/persons.json`, ~13K curated entries that bump rarely on stub merges or Wikidata enrichment, not on the daily-cron timeline). Orphan-delete fires on registry shrinkage, pulling the abandoned `/politicieni/<slug>` page out of `mo-persons` so the public site never serves a stale entry. Webhook stub for ISR invalidation gated behind `MONITORUL_ISR_WEBHOOK_URL` (logs `(grain, record_id)` pairs for now; live HTTP call deferred to P5). Run **after** `extract` / `link` / `backfill` (and any enrichment producers); per the design doc's daily-cron flow `fetch → convert → extract → link → backfill → enrich → index → sitemap`.

The bootstrap key passed via `ES_API_KEY` needs cluster admin to install templates / create indices / mint role-scoped keys; rotate to `monitorul_reader` / `monitorul_indexer` for downstream use after `es-init` completes. ES is *not* the system of record (sidecars on disk + S3 are SOT) and rebuilds overnight from sidecars per `docs/elasticsearch-indexing.md` § Disaster recovery.

`EMBED_URL` (also `.env`-loaded; default `http://127.0.0.1:8000`) points at the BGE-M3 embedding service in `services/embed/`. Read by `monitorul-ii embed` (when `--embed-url` isn't passed) and by `monitorul-ii query` when `rank_fusion="rrf"` or `"knn-only"` requires vectorising the query text. The service is stateless and not the system of record — vector files on disk + S3 are SOT.

`OPENROUTER_API_KEY` (also `.env`-loaded) is required for `monitorul-ii analyze` — the discourse-analysis pipeline calls OpenRouter's OpenAI-compatible `POST /chat/completions`. `OPENROUTER_URL` (optional; default `https://openrouter.ai/api/v1`) overrides the endpoint. The CLI fails fast (exit 2) when the key is missing on a non-dry-run; `--dry-run` short-circuits before any auth check. The service is external (third-party); discourse JSON files on disk + S3 are SOT.

A SQLite audit log at `data/monitorul.db` (override `--db PATH`, disable `--no-db`) gates whether each day's index POST happens. `days.status='ok'` past days short-circuit the index fetch on resume — including weekends and empty days that have zero Partea II issues. The filesystem and bucket still gate per-PDF skip; the DB doesn't pretend to know whether a file actually exists. `--reverse` walks newest→oldest. `--force` ignores the DB skip; `--rescrape-recent N` re-fetches the last N days regardless of status (today is always re-fetched). See `docs/architecture.md` for the schema and resume contract.

Per-request retries: 3 attempts with backoff `1s → 2s → 4s` for transient errors (5xx, 429, transport). 4xx-not-429 / parse / content-type errors raise immediately. Failures are then classified at the call site: **transient → `status='failed'`** (auto-retried on the next run); **permanent → `status='gone'`** (terminal — content-type mismatch or 4xx-not-429, which mean the server doesn't have the resource as a PDF; not auto-retried, treated like `downloaded`/`uploaded` by the resume gate). `--retry-gone` resets every `gone` row back to `pending` for one-off recovery if the source site restores missing documents. `attempts` is informational.

PDFs land directly in `<out>/<YYYY-MM-DD>_MO-P<part>-<num>-<year>.pdf` (no per-day subdirectory — the date is in the filename so everything sorts chronologically in one folder). Re-runs skip files already on disk; partial downloads write to a `.part` file and are renamed atomically on success. Sha256 + size land in the DB during streaming download (or lazily during the existing-file skip path).

`convert` produces `<basename>.md` next to each `<basename>.pdf` via `pymupdf4llm.to_markdown` plus an MO-specific cleanup pass (strips per-page `MONITORUL OFICIAL...` running headers, image placeholders, standalone page numbers; joins hyphenated word breaks; collapses extra blank lines) and a YAML frontmatter prepend (`issue`, `year`, `part`, `published` from the filename; best-effort `chamber`, `session`, `session_date`, `legislature` parsed from the first ~5 KB of body — graceful fallback if any field can't be detected). Idempotent: skip when `.md` exists & non-empty; `--force` re-converts. MDs mirror to S3 with `Content-Type: text/markdown` (same bucket, flat key). The DB is *not* extended for MD state — filesystem + `head_object` cover idempotency.

Conversion is parallelized via `ThreadPoolExecutor(-j N)`. PyMuPDF releases the GIL during PDF parsing so threads scale on multi-core. `cli.py` sets `OMP_NUM_THREADS=1` + `ORT_INTRA_OP_NUM_THREADS=1` via `setdefault` *before* importing `pymupdf4llm`, otherwise the layout model's ORT session auto-spawns its own intra-op pool that fights the outer workers for cores (8 PDFs measured: 110 s default → 28.7 s with the env vars + `-j 8`, 3.8× speedup). Events fire in completion order (not input order); `on_event` runs in the calling thread to keep S3 uploads serialized without locks. Throughput plateaus around `-j 8` on the 20-core test box. **No GPU path** — `pymupdf-layout` hardcodes one of its two ORT sessions to `CPUExecutionProvider`, so `onnxruntime-gpu` would only accelerate half the work; not worth the ~3 GB install.

`convert` shows progress identically to `fetch`: a live `rich` bar on stderr when isatty (PDF count, %, elapsed, ETA, running converted/skipped/errors + s3 totals), or a `progress: …` heartbeat every `_CONVERT_HEARTBEAT_EVERY` PDFs in pipes. The reporter is a context-manager (`with _ConvertProgressReporter(total, counters) as report`); `report.print(line, err=…)` writes lines above the bar (or to stdout/stderr in heartbeat mode), `report.advance()` ticks the bar and emits heartbeats. Counters are a single mutable dict shared by `cmd_convert`'s closure and the reporter — bumping a counter inside `on_event` is reflected in the next bar redraw. Ctrl+C: `convert_all`'s parallel branch wraps `as_completed` in `try/except KeyboardInterrupt` and calls `ex.shutdown(wait=True, cancel_futures=True)` before re-raising; `cmd_convert` catches the KbdInt and prints `interrupted: converted=… skipped=… errors=… | s3 …` (using the live counters) before returning 130. The `wait=True` is intentional — letting in-flight workers finish their current PDF means no half-written `.md` files and no atexit thread-join race that would otherwise dump a traceback.

`classify` is the type detector — step 1 of the extraction pipeline (see `docs/extraction-schema.md` build order). Pure-regex sweep over each MD's filename suffix + first 10 KB of body, scoring each of the six document types (`plenary_stenogram | plenary_joint_session | committee_synthesis | report_facsimile | question_register | other`). Output is one JSONL row per file to stdout with `{file, top_type, top_score, second_type, second_score, ambiguous, all_scores, matched_signals}`; summary counts to stderr. `--outliers` filters to docs that landed in `other` or are flagged ambiguous — the latter excludes structural co-evidence (joint_session ⊃ stenogram, report received in joint session) via `_COMPATIBLE_RUNNERS_UP`. On the 2300+ doc corpus the sweep runs in <2 s and (as of v1.3.0 schema rules) lands every document into a typed bucket with zero residual outliers.

`extract` is the structuring step — step 2 / step 1.5 of the extraction pipeline (`docs/extraction-schema.md` build order, revised). Reads each MD, splits the YAML frontmatter into `metadata`, classifies it, dispatches to `EXTRACTORS[doc_type]`, merges the extractor's record claims with the shared `claim_shared_boilerplate` output, computes coverage, calls `assign_identity` to mint per-record `id` / `content_fingerprint` / `slug` (reading any prior sidecar to enforce slug-once), builds the envelope (carrying per-component `extractor_versions`: `boilerplate / coverage / identity / references / speakers / topics / <doc_type>` + an `extraction.identity` block whose `record_id` mirrors `document_id`), validates the full sidecar against `extraction_schema.json` strictly, and writes `<basename>.extraction.json` atomically next to the MD. **Version-aware idempotency**: an existing sidecar is reused iff its `schema_version` AND every key in `extractor_versions` matches the runtime; mismatch re-extracts automatically. `--force` overrides. `--identity-only` opens an alternative fast path: read the existing sidecar's body, run `assign_identity` over it, bump only `extractor_versions.identity` + `schema_version`, rewrite atomically. This avoids re-running per-type extractors during the schema-1.13.0 backfill (~30 minutes saved on the 5552-doc corpus). Schema validation runs **pre-write**: a violation never lands a malformed sidecar on disk; the rejected dict is dumped to `<basename>.rejected.json` for inspection. Source-span coordinate system locked: 0-indexed half-open char offsets into the **body text** (post-frontmatter); 1-indexed inclusive line numbers; `content_sha` = sha256 of body bytes truncated to 12 hex chars. Coverage is **diagnostic-only** — `--coverage-below MARGIN` emits JSONL rows to stdout for the discovery loop, but never blocks writes. v0.1 ships all six per-type extractors: `question_register` (53-doc cohort, p50 coverage 99.7%), `plenary_stenogram` (2240-doc cohort), `plenary_joint_session` (~50-doc cohort), `committee_synthesis` (976-doc cohort, mean 0.997, median 1.000, p25 0.999, min 0.886), and `report_facsimile` (52-doc cohort, mean 0.999, median 0.999, min 0.970, zero errors). Coverage targets per Q9 are **discovery margin 0.85**, **test fixture floor 0.80**, **mean target 0.90 documented (ungated)**. Five hand-picked plenary fixtures span modern joint, modern Camera, modern Senat, mid-2017, and older 2013 layouts; four committee_synthesis fixtures span 2008/2018/2022/2025 (narrative + tabular + mojibake + pandemic-era); four report_facsimile fixtures span 2014 image-only CSAT, 2014 SRI, 2017 Consiliul Legislativ, 2024 ANCOM (rich modern body); suite enforces ≥0.80 per fixture. When `S3_*` env vars are set, sidecars mirror with `Content-Type: application/json`. Sequential by design — regex sweeps hold the GIL, parallelism would buy nothing.

**After each code change, run `uv run ruff format` and `uv run ruff check --fix` before reporting the task complete.**

**Tests are mandatory for every new feature, in the same change. Non-negotiable.** A "feature" here means any new function, CLI flag, regex, parser branch, DB column, state-transition, or behavior change. The bar is:

- **New pure function** → at least one happy-path test plus one rejection / edge case (empty input, malformed input, boundary).
- **New CLI flag** → one test that exercises the flag's effect (parser-level via `_build_parser` or behavior-level via the helper it toggles). Don't test argparse itself; test the branch it switches on.
- **New regex / parser branch** → one positive sample, one negative sample, and one for any quirk you encoded (e.g. legacy glyph mapping, suffix tolerance).
- **New DB state transition** → one test that drives the transition and asserts the row, plus one for the idempotency / re-entry case if the transition is callable twice.
- **New scraper / converter behavior** → drive `scrape_day` or `convert_all` end-to-end with `httpx.MockTransport` / `monkeypatch.setattr(converter, "convert_pdf", ...)` so the orchestration layer is covered, not just the leaf function.

Tests live in `tests/` mirroring `src/monitorul_ii/` (`test_<module>.py`). `tests/conftest.py` exposes a `db` fixture (`DB(tmp_path/"audit.db")`). **Do not** add tests that touch the network, real S3, or real PDFs — every external boundary has a stub already; use it. **Run `uv run pytest` before reporting the task complete; the suite must be green.**

**If a code change breaks tests, fix the tests in the same change — don't leave a red suite.** When tests fail because the production code's contract changed (renamed paths, refactored APIs, removed helpers), update the tests to match the new contract; don't revert the code or skip the tests. Only treat a test failure as a real bug to fix in production code when the test is asserting still-intended behavior.

**Document every new feature, in the same change. Non-negotiable.** A feature is shipped only when *all three* docs reflect it:

- `README.md` — user-facing prose. Every CLI flag must be described in prose (not just shown in an example), including its semantics, default, and any non-obvious interaction with other flags or env vars. If you added a flag, search README to confirm its name appears in a sentence, not only inside a code fence.
- `CLAUDE.md` (this file) — agent-facing scannable summary. The "Commands" section's CLI signature must include the new flag; the prose paragraph for the relevant subcommand must mention any new behavior, default, or dep.
- `docs/architecture.md` — deep mechanics: *why* the flag exists, what tradeoffs it encodes, what was tried and rejected, measured numbers if relevant.

"Meaningful" = a new CLI flag, a new behavior or default, a new module, a new external dependency, a new env-var the CLI reads or sets, a new failure mode, or anything a future user/agent would otherwise have to read the diff to discover. Touching `pyproject.toml` `[project.dependencies]` always counts.

**Keep CLAUDE.md scannable** — push detailed mechanics into `docs/architecture.md` and link from here. CLAUDE.md is the index; architecture.md is the manual.

**Self-check before reporting the task complete:**

1. `uv run pytest` is green and exercises the new code path (don't trust pre-existing coverage).
2. `uv run ruff format` and `uv run ruff check --fix` clean.
3. For each new flag, `grep -n '<flag-name>' README.md CLAUDE.md docs/architecture.md` shows hits in all three. If any miss, write the missing doc *now*, not "as a follow-up".

## uv-on-snap quirk

`uv` installed via snap buffers stdout when there is no tty, so `uv run <cmd>` may appear silent in non-interactive shells. Pipe through `cat` (e.g. `uv run monitorul-ii --help | cat`) or invoke the venv binary directly (`.venv/bin/monitorul-ii ...`) when you need to see output.

## Release flow

Releases are automated via [release-please](https://github.com/googleapis/release-please) (`.github/workflows/release-please.yml`), triggered on every push to `main`.

- Tags include the component name (`include-component-in-tag: true`)
- Pre-1.0: minor bumps for features (`bump-minor-pre-major: true`)
- Version source of truth for release-please is `.release-please-manifest.json`, **not** `pyproject.toml` — keep them in sync if bumping manually
- Commits must follow Conventional Commits for release-please to pick them up (`feat:`, `fix:`, `chore:`, etc.)
